- ECS-144: the Player model has no position, so GET /api/players returns id, name, nationality, current club and latest market value, and storing position became ECS-162. The current club is the buyer of the player's latest transfer. Accent-insensitive search widens each letter of the query into its accented variants in a regex, so no extra normalized-name field is needed. q needs at least 2 characters; the limit defaults to 20 and is capped at 50; club filters by the club's Mongo id. Player ids in the API are Mongo ids.

- ECS-145: GET /api/players/:id returns id, name, birth date, nationality, current club (buyer of the latest transfer), latest and peak market value. Position waits on ECS-162. On equal peak values the most recent one wins. Invalid ids return 400, unknown ids 404.
- ECS-146: GET /api/players/:id/market-values returns { marketValues: [{ date, value }] } oldest first. from and to are inclusive and accept 2024-06-01 or full ISO timestamps; from after to is a 400. Unknown players get a 404, and a known player with no values gets an empty list.
- ECS-147: the search page debounces input by 300 ms, needs 2 characters, and uses switchMap so a slower older answer never replaces a newer one. Results link to /players/:id, which ECS-148 will add (until then that URL falls back to /players).
- Market values come from the latest player_valuations row of the transfermarkt-datasets snapshot, which matches the players table value (checked by Tim on Lacazette and Drogba). They can lag Transfermarkt's site when the local snapshot is old, and stop when a player leaves the tracked leagues or retires, so the UI always shows the valuation date next to the value.
- ECS-163 (Tim's rule): a player's latest market value is current only if it is no older than one market window (6 months) before the newest valuation in the database; otherwise the API returns null (shown as "Valeur inconnue"). The cutoff follows the dataset, not today's date, so an old snapshot still shows values. The peak value and the time series keep the full history. MarketValue gained a { date: -1 } index for finding the newest valuation.
- ECS-148: the player page at /players/:id loads the profile and the history together (forkJoin), treats 404 and 400 as "Joueur introuvable", and reloads when the id changes. The chart uses a category x-axis, so points are evenly spaced rather than proportional to time; a time axis would need the chartjs date adapter.
- ECS-149: GET /api/players/:id/transfers returns { transfers: [{ date, fromClub, toClub, fee }] } oldest first; fromClub is null without a seller and fee is null when the dataset has none (free or undisclosed), while 0 stays 0. On the chart, each transfer sits on the valuation closest in time (the x-axis has one label per valuation) and takes that value; transfers before the first or after the last valuation are left out, and transfers on the same valuation share one marker. A failed transfers request only hides the markers, and the page says so under the chart (also when the player has no transfers or all of them fall outside the valuation history), after Tim saw no markers locally. The shared line chart gained optional marker-only series (showLine false, triangles) and per-point tooltip text.
- ECS-150: transfer ROI rules live in backend/src/services/transferRoi.js as pure functions. Fee paid is the transfer fee (null when unknown, 0 stays 0). Market value at signing is the closest valuation on or before the transfer date. Tim's loan rule: only a permanent departure ends the player's stay; loan fees received along the way are added to what the club gets back (bought 10M, loaned out for 3M, sold for 10M = +3M). The dataset has no loan flag, so findExit treats a move from the buying club to X as a loan when the player's next move is X back to the buying club with no fee (0 or null) within MAX_LOAN_DAYS (731); a fee on the way back is a buy-back, so the first move was a sale. A loan fee of null counts as 0. A loan with no return row yet counts as a sale. A paid move out that is followed by a free return and then a free move back to the same buyer is a sale with a loan back (Malo Gusto to Chelsea, Lucas Tousart to Hertha), not a paid loan; the loan back shows as a loan in the buyer-club's list. The exit is the first non-loan move away ("resale", value = its fee + loan fees, null when the fee is unknown), or, when he never left, his latest valuation if current under the ECS-163 rule ("marketValue", value = valuation + loan fees, otherwise null); exit.loanFees carries the loan part. Gain is exit value minus fee paid; ROI is gain over fee paid in percent, rounded to one decimal, and null when the fee paid is 0 or anything needed is unknown. Callers must pass buyer and seller ids on every transfer so loans can be detected, and spread findExit's result into computeTransferRoi (ECS-151 and ECS-152 need updating).
- ECS-151: GET /api/clubs/:id/transfers/roi returns { transfers, totals } with the club's incoming transfers oldest first, each with player, date, seller (fromClub) and the ECS-150 ROI fields. The optional season query takes a Season Mongo id. Totals skip unknown amounts: totalSpent sums known fees, totalCurrentValue sums current valuations of players still at the club, totalResaleIncome sums known resale fees, totalLoanIncome sums loan fees earned from players loaned out (kept out of the other two sums), and netGain sums only the gains that are known, so it can differ from income minus spending. Loan rule (Tim): a player coming back from a loan the club gave him is not a signing, so loanStatus drops those returns from the list; players the club took on loan stay in the list with isLoan true.
- ECS-152: GET /api/players/:id/transfers/roi returns { transfers } oldest first, each with date, fromClub, toClub and the ECS-150 ROI fields from the buying club's point of view. The exit of each transfer follows the ECS-150 loan rule (first move away that is not a loan out, plus loan fees; current valuation when he never left for good). Loan returns are left out of the list and the start of a loan is flagged with isLoan. No totals are returned for a player.
- ECS-153: GET /api/clubs returns { clubs: [{ id, name, country }] } sorted by name; without a filter it lists the synced league's clubs (isExternal not set), and ?league=<competitionId> (e.g. FR1) lists clubs with a ClubSeason in that league. GET /api/seasons returns { seasons: [{ id, period, startDate, endDate, league }] } newest first, with the same optional league filter. An unknown league gives an empty list; a malformed one is a 400. Olympique Lyonnais as the default is left to the UI pages.
- With 6 loop PRs open after the 08:54 run, that run did not chain, since the next run would only hit the backlog brake.
- ECS-154: /transfer-roi loads GET /api/clubs and GET /api/seasons together, selects the first club whose name contains "Lyon" (else the first club), and loads GET /api/clubs/:id/transfers/roi for the club and the optional season (switchMap, so a slower old answer never replaces a newer one). Five cards show Dépenses, Valeur actuelle, Reventes, Prêts and Gain net (with how many signings have a known gain). The table sorts by date, player, fee paid, amount recovered, gain or ROI; unknown values always sort last, and names sort in French order. Loans in carry a "Prêt" badge and their exit reads "Fin du prêt"; the amount recovered notes how much came from loan fees. Checked against the real Lyon data on Tim's local server (144 signings, net gain 168.9M).
- ECS-155: the player page loads GET /api/players/:id/transfers/roi alongside the profile, history and transfers; a failure only replaces the ROI section with a message. The section lists each transfer oldest first (from X to Y, or "Arrivée à Y" without a seller, with a "Prêt" badge for loans) with fee paid, value at signing, amount recovered (resale or current value, plus loan fees), gain and ROI, reusing the wording of the club ROI page. Loan returns are not listed, as the endpoint drops them. The PlayerTransferRoi model reuses TransferExit from the transfer-roi feature.
- From PR #20 on, branches follow the loop/pr-<N>-<slug> naming.
- PR #21 (asked by Tim, merged): the club ROI page has a league picker (Ligue 1 by default) and opens on the latest season; the season filter matches the season's period in any league. Achats show Valeur actuelle after Joueur, Gain de valeur depuis l'achat (current value minus fee) and Gain à la revente (sale fee minus fee); Date, Valeur à la signature and Montant récupéré are in a toggled detailed view. Ventes show a Gain column (sale fee plus loan fees minus what the player cost the club, 0 when formed there). The player page judges each transfer for the selling club. An unknown fee between a club and its own reserve or youth team (Lyon B, Marseille U19, ...) counts as 0 (backend/src/services/reserveTeam.js).
- ECS-162: Player gained position and subPosition (dataset "Missing" and empty values become null). The players reader selects position and sub_position, a re-sync refreshes them on known players, and GET /api/players and GET /api/players/:id return them as the dataset's English values. Showing them in French in the UI is ECS-166.
- ECS-156 squad membership rule: a player is in a club's squad for a season when his latest transfer on or before the season's end date has the club as buyer (a player on loan at the end counts for the loan club). Players with no transfer in the data cannot be placed and are left out. Each player is valued at his latest valuation on or before the reference date, which is the season's end date or the newest valuation in the data when the season is not over; a valuation older than one market window before that date counts as unknown and is left out of the totals. Totals per position use Goalkeeper, Defender, Midfield, Attack, then unknown (null). Lives in backend/src/services/squadValueService.js (computeSquad is pure).
- ECS-157: GET /api/clubs/:id/seasons/:seasonId/squad-value returns the ECS-156 result as is; 400 for an invalid club or season id, 404 when either does not exist.
- ECS-158: GET /api/clubs/:id/squad-value/history returns { club, seasons: [{ season, referenceDate, totalValue, playerCount, valuedPlayerCount }] } oldest first, one entry per season the club has a ClubSeason row for (so only seasons in a synced league), with the ECS-156 rules. The club's players are loaded once for every season. 404 for an unknown club.
- ECS-159: the squad value page at /squad-value has the same league, club and season pickers as the ROI page (Ligue 1, Lyon, latest season by default; there is no "all seasons" option), reusing TransferRoiService for the picker lists. It shows the total value with its reference date, the player count, one card per position, the evolution chart from the history endpoint (a failure only hides the chart) and the players sorted by value. Positions are shown in French by main position only (Gardien, Défenseur, Milieu, Attaquant); sub-positions wait for ECS-166.
- ECS-160: `npm run seed:demo` (backend/src/jobs/seedDemo.js) loads backend/src/jobs/demo/demoData.js: Ligue 1, three seasons, nine clubs (Lyon, Monaco and PSG play in the league), eight demo players with positions, their transfers and valuations. The figures are rounded examples, not real data. It upserts by natural keys and replaces only the demo players' transfers and valuations, so it is safe to re-run. It refuses mongodb+srv:// URIs unless SEED_ALLOW_REMOTE=1. Loading is tested against mongodb-memory-server in CI.
- ECS-166: French position labels live in frontend/src/app/shared/positions.ts (moved from the squad value feature). The player page header says "Poste : Attaquant, avant-centre." and search results show the position in brackets after the club; the sub-position is dropped for goalkeepers or unknown values, and nothing is shown when both are unknown.
- ECS-164 (backend part): inflation uses euro area HICP (annual averages, 2015 = 100) stored in backend/data/seeds/hicp-euro-area.json. The values were typed in without a download because the sandbox cannot reach Eurostat, and 2025 is an estimate, so Tim should verify them. Each amount is multiplied by index(reference year) / index(year of the amount); fees use the transfer date's year and market values the valuation date's year; the reference year defaults to the table's latest year; years outside the table use its first or last year. The index is pluggable (createIndex), so a transfer market index can be added later. Both ROI endpoints keep their nominal fields and add adjusted ones. The pages' nominal/adjusted toggle is ECS-168.
