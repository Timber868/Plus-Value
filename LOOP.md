- ECS-146: GET /api/players/:id/market-values returns { marketValues: [{ date, value }] } oldest first. from and to are inclusive and accept 2024-06-01 or full ISO timestamps; from after to is a 400. Unknown players get a 404, and a known player with no values gets an empty list.
- ECS-147: the search page debounces input by 300 ms, needs 2 characters, and uses switchMap so a slower older answer never replaces a newer one. Results link to /players/:id, which ECS-148 will add (until then that URL falls back to /players).
- Market values come from the latest player_valuations row of the transfermarkt-datasets snapshot, which matches the players table value (checked by Tim on Lacazette and Drogba). They can lag Transfermarkt's site when the local snapshot is old, and stop when a player leaves the tracked leagues or retires, so the UI always shows the valuation date next to the value.
- ECS-163 (Tim's rule): a player's latest market value is current only if it is no older than one market window (6 months) before the newest valuation in the database; otherwise the API returns null (shown as "Valeur inconnue"). The cutoff follows the dataset, not today's date, so an old snapshot still shows values. The peak value and the time series keep the full history. MarketValue gained a { date: -1 } index for finding the newest valuation.
- ECS-148: the player page at /players/:id loads the profile and the history together (forkJoin), treats 404 and 400 as "Joueur introuvable", and reloads when the id changes. The chart uses a category x-axis, so points are evenly spaced rather than proportional to time; a time axis would need the chartjs date adapter.
- ECS-149: GET /api/players/:id/transfers returns { transfers: [{ date, fromClub, toClub, fee }] } oldest first; fromClub is null without a seller and fee is null when the dataset has none (free or undisclosed), while 0 stays 0. On the chart, each transfer sits on the valuation closest in time (the x-axis has one label per valuation) and takes that value; transfers before the first or after the last valuation are left out, and transfers on the same valuation share one marker. A failed transfers request only hides the markers, and the page says so under the chart (also when the player has no transfers or all of them fall outside the valuation history), after Tim saw no markers locally. The shared line chart gained optional marker-only series (showLine false, triangles) and per-point tooltip text.
- ECS-150: transfer ROI rules live in backend/src/services/transferRoi.js as pure functions. Fee paid is the transfer fee (null when unknown, 0 stays 0). Market value at signing is the closest valuation on or before the transfer date. Tim's loan rule: only a permanent departure ends the player's stay; loan fees received along the way are added to what the club gets back (bought 10M, loaned out for 3M, sold for 10M = +3M). The dataset has no loan flag, so findExit treats a move from the buying club to X as a loan when the player's next move is X back to the buying club with no fee (0 or null) within MAX_LOAN_DAYS (731); a fee on the way back is a buy-back, so the first move was a sale. A loan fee of null counts as 0. A loan with no return row yet counts as a sale. A paid move out that is followed by a free return and then a free move back to the same buyer is a sale with a loan back (Malo Gusto to Chelsea, Lucas Tousart to Hertha), not a paid loan; the loan back shows as a loan in the buyer-club's list. The exit is the first non-loan move away ("resale", value = its fee + loan fees, null when the fee is unknown), or, when he never left, his latest valuation if current under the ECS-163 rule ("marketValue", value = valuation + loan fees, otherwise null); exit.loanFees carries the loan part. Gain is exit value minus fee paid; ROI is gain over fee paid in percent, rounded to one decimal, and null when the fee paid is 0 or anything needed is unknown. Callers must pass buyer and seller ids on every transfer so loans can be detected, and spread findExit's result into computeTransferRoi (ECS-151 and ECS-152 need updating).
- ECS-151: GET /api/clubs/:id/transfers/roi returns { transfers, totals } with the club's incoming transfers oldest first, each with player, date, seller (fromClub) and the ECS-150 ROI fields. The optional season query takes a Season Mongo id. Totals skip unknown amounts: totalSpent sums known fees, totalCurrentValue sums current valuations of players still at the club, totalResaleIncome sums known resale fees, totalLoanIncome sums loan fees earned from players loaned out (kept out of the other two sums), and netGain sums only the gains that are known, so it can differ from income minus spending. Loan rule (Tim): a player coming back from a loan the club gave him is not a signing, so loanStatus drops those returns from the list; players the club took on loan stay in the list with isLoan true.
- ECS-152: GET /api/players/:id/transfers/roi returns { transfers } oldest first, each with date, fromClub, toClub and the ECS-150 ROI fields from the buying club's point of view. The exit of each transfer follows the ECS-150 loan rule (first move away that is not a loan out, plus loan fees; current valuation when he never left for good). Loan returns are left out of the list and the start of a loan is flagged with isLoan. No totals are returned for a player.
- ECS-153: GET /api/clubs returns { clubs: [{ id, name, country }] } sorted by name; without a filter it lists the synced league's clubs (isExternal not set), and ?league=<competitionId> (e.g. FR1) lists clubs with a ClubSeason in that league. GET /api/seasons returns { seasons: [{ id, period, startDate, endDate, league }] } newest first, with the same optional league filter. An unknown league gives an empty list; a malformed one is a 400. Olympique Lyonnais as the default is left to the UI pages.

- ECS-156 squad membership rule: a player is in a club's squad for a season when his latest transfer on or before the season's end date has the club as buyer (a player on loan at the end counts for the loan club).
